# AI 모델 학습 및 홀드아웃 검증

## 왜 홀드아웃을 쓰나요?

과거 데이터에 잘 맞춘 모델이 다음 거래일에도 통하는지 확인하려면, 모델이 학습이나 설정 선택에 사용하지 않은 날짜를 남겨 두어야 합니다. 마지막에 남겨 둔 날짜 구간을 **독립 홀드아웃**이라고 합니다.

주식 데이터는 시간이 흐르는 순서가 중요합니다. 미래 시세가 과거 판단에 섞이지 않도록 행을 무작위로 섞지 않고, 거래일 단위로 과거에서 미래 방향으로 나눕니다.

```text
과거                                                          미래
|------ 학습 ------|-- 검증 --|-- 내부 시험 --|------ 독립 홀드아웃 ------|
  모델 학습          후보 선택    학습 단계 점검    최종 비교에 한 번만 사용
```

학습·검증·내부 시험은 후보를 만들고 고르는 과정에 사용합니다. 후보의 설정을 고정한 뒤에야 그보다 뒤의 독립 홀드아웃 구간을 엽니다. 홀드아웃 결과를 보고 설정을 바꾸면 그 구간은 더 이상 독립적인 최종 확인 자료가 아니므로, 새로 모은 이후 거래일 자료로 다시 확인해야 합니다.

## 이 프로젝트의 확인 순서

1. 완전한 정규장 1분봉, 호가 스프레드, 승인된 KIS WebSocket 출처가 있는 거래일만 적격 자료로 인정합니다. KIS 권리 확인 manifest와 CSV 해시도 검사합니다.
2. 모델 학습에는 최소 13개의 적격 거래일이 필요합니다. 거래일 순으로 학습·검증·내부 시험을 나누며, 준비도 API와 대시보드는 각 구간의 양성·음성 표본 수를 함께 표시합니다. 학습 구간에 두 결과 클래스가 없으면 후보 모델을 만들지 않습니다.
3. 검증 구간의 Brier 점수로 홀드아웃 평가 후보 하나를 고릅니다. 내부 시험 및 학습 자료의 날짜가 홀드아웃보다 앞서는지도 확인합니다.
4. 후보와 설정을 고정하고, 이후 최소 5개의 완전한 거래일을 독립 홀드아웃으로 평가합니다. 따라서 승인 준비에는 학습용 13일과 이후 홀드아웃 5일, 최소 18개의 서로 다른 적격 거래일이 필요합니다. 같은 후보나 같은 시장·종목의 홀드아웃 날짜를 다시 쓰지 않습니다.
5. 실제 PAPER 운용과 같은 ORB/VWAP 조건 뒤에 AI 확률 조건을 적용합니다. 수수료·세금·슬리피지를 포함한 손절·익절 백테스트를 퀀트 단독 기준선과 비교합니다.
6. 결과는 후보의 증거로 기록하지만 자동 승인·활성화·주문은 하지 않습니다. 운영자 승인 기준에는 최소 5개 홀드아웃 체결, 양의 순손익, 그리고 같은 구간 퀀트 기준선보다 나은 순손익이 포함됩니다.

LightGBM과 XGBoost 비교 학습은 한 후보라도 학습·평가·아티팩트 저장에 실패하면, 그 호출에서 먼저 만들어진 미승인 후보 파일도 제거하고 실패로 끝납니다. 따라서 중단된 비교 실행의 일부 결과가 나중에 홀드아웃 후보 선택에 섞이지 않습니다. 이미 만들어진 후보나 승인 기록은 이 정리 대상이 아닙니다.

평가 지표에는 정확도와 Brier 점수 외에도 실제·예측 양성 비율, 양성 정밀도·재현율, 특이도, 균형 정확도를 기록합니다. 거래 신호가 드문 데이터에서 음성만 맞혀 정확도가 높게 보이는 상황을 구분하기 위해서입니다. 표본에 양성 또는 음성 사례가 없어 계산할 수 없는 지표는 0으로 꾸미지 않고 unavailable로 둡니다. 어떤 단일 분류 지표도 후보를 승인하지 않습니다. 거래가 거의 없거나 실제 계좌 비용 가정이 빠진 결과는 성능 확인을 통과한 것으로 보지 않습니다. 이 검증은 과거의 독립 구간에서 모델을 비교하는 절차이며 미래 수익이나 실전 안전을 보장하지 않습니다.

## 현재 운영 조건

학습·홀드아웃 실행기는 `.env_local`의 PAPER 모드와 PAPER/REAL 주문·자동매매 잠금을 다시 확인합니다. 입력된 시장별 수수료, 매도세, 슬리피지, 왕복 레이블 비용이 유효하지 않으면 데이터 내보내기와 평가를 시작하지 않습니다. 실계좌 주문 잠금은 계속 비활성으로 유지합니다.

현재 적격 세션 수와 예약 작업 결과는 [개발 로드맵](roadmap.md)에서 확인하세요. 준비도 숫자나 예약 상태만으로 모델 학습·홀드아웃 성능이 검증된 것은 아닙니다.
