# AI Stock Trader v1.0 Roadmap

## 방향

AI와 퀀트 전략 결합형 국내·미국 당일매매 시스템입니다. 기본 증권사는 KIS Open API입니다. NautilusTrader와 강화학습은 사용하지 않습니다.

초기 운영 한도(종목당 자산 10%, 거래당 0.25%, 일일 손실 1%, 최대 3종목, 연속 손절 3회)는 전략 검증용 시작값이며 수익 보장이나 최적값이 아닙니다. 설정값으로 관리하고, 고정 상수로 매매 판단에 박아 넣지 않습니다.

## 단계와 통과 기준

1. **P1 — KIS 연결 기반:** 별도 paper/real 인증, 국내·미국 잔고·주문가능 금액, WebSocket·호출 제한·마스킹. Mock과 paper 통합 조회를 검증하며 주문은 비활성화.
2. **P2 — 주문 엔진:** 매수·매도·정정·취소, 부분체결·중복 차단·재시작 복구. 모의 전 과정과 장애 시나리오를 통과.
3. **P3 — 퀀트:** VWAP, ORB, EMA, ATR, 유동성, 비용 모델. 과거 데이터 결과 재현과 미래 데이터 누수 방지.
4. **P4 — AI:** LightGBM/XGBoost, 피처·모델 버전·실시간 추론. 미사용 데이터에서 퀀트 대비 성능 비교.
5. **P5 — 자동 모의운영:** 국내·미국 시장 세션, 장 마감 관리, 장애 시나리오. 연속 모의 세션에서 안정성 확인.
6. **P6 — KIS 주문 엔진:** 모의 주문·취소 어댑터, 계좌잔고/주문가능금액 사전검사, 영속 중복방지와 불명 결과 잠금을 구현합니다. 주문 의도에는 PAPER/REAL 환경을 명시적으로 저장해 계좌별로 구분합니다. 실제 주문은 별도 승인 절차와 검증 기준을 통과하기 전까지 비활성화합니다.
7. **P7 — 운영·성과 개선:** 상태 대시보드, 일일 리포트, 시장별 모델 분리, 승인·활성화·롤백 감사 기록을 구현합니다. 운영 완료 기준에는 P1 계좌 연결, P5 연속 모의세션, 체결비용을 포함한 손익 대조와 검증된 데이터가 추가로 필요합니다.

## 구현 현황 (2026-11-06)

1. **P1:** Spring REST 읽기 전용 계좌·잔고 기반과 Python REST/WebSocket 시세 연결을 구현했습니다. 양쪽 계좌조회는 전체 허용 스위치와 PAPER/REAL 환경별 스위치를 모두 확인해 REAL 조회가 기본 차단되도록 했습니다. 국내·미국 잔고 응답은 KIS의 연속 조회 헤더·커서를 따라 최대 20페이지까지 병합하고, 한도를 넘으면 불완전한 보유 목록 대신 오류로 닫습니다. 해외 잔고의 `output1` 보유 종목과 `output2` 요약을 공식 예제 형식에 맞췄습니다. 모의 체결기준 잔고 응답의 `output3.tot_asst_amt`는 총자산 평가액으로 분류하고 현금/주문가능액으로 오인하지 않도록 했습니다. 계좌별 현금 필드가 없는 경우 현금값은 미확인(null)으로 두며, 종목별 매수가능액은 별도 API 조회를 사용합니다. Python 계좌 클라이언트는 환경별 토큰 캐시를 재사용하고 앱 종료 시 HTTP 클라이언트를 닫습니다. 공유 제한 DB 오류는 Python API에서 HTTP 503으로 반환합니다. Python과 Spring은 PostgreSQL `kis_rest_rate_limit_slot`에서 환경·앱키 SHA-256 지문별로 슬롯을 원자 예약하여 프로세스 간 호출 간격을 공유합니다. Spring 4개 작업자와 Python 5개 작업자의 동시 예약을 실제 로컬 PostgreSQL로 검증했고, 앱키 원문은 저장되지 않습니다. DB에서 예약할 수 없으면 KIS 요청을 보내지 않습니다. `test-paper-kis.ps1`, Python FastAPI 국내·미국 시세 및 계좌 GET 스모크 `test-paper-kis-python.ps1`, 잠금 조건을 확인하는 `test-real-kis-account-readonly.ps1`을 준비했으며, 운영 요약은 비밀값 없이 PAPER/REAL 키 입력 및 10자리 계좌번호 형식 상태를 표시합니다. `.env_local`에 PAPER 인증값과 조회 잠금이 설정되어 있습니다. 사용자가 PAPER 계좌를 재등록하고 `.env_local`의 PAPER 계좌·키를 교체한 뒤, 2026-11-06 Spring PAPER 국내·미국 잔고 GET 통합 테스트 2건이 모두 통과했습니다. 이전 `OPSQ2000` 연결 오류는 갱신된 모의 계좌 등록/설정으로 해결되었습니다. REAL 조회와 모든 주문은 계속 잠겨 있습니다. WebSocket과 계좌 조회는 기본 잠금입니다.
2. **P2:** PostgreSQL 기반 paper 주문, 부분체결, 체결 중복 키, 포지션·현금 정산, 취소·만료와 기본 한도 검증이 있습니다. paper 주문 삽입은 PostgreSQL의 멱등 키 충돌 원자 처리를 사용하고, 만료 스케줄러는 paper 모드에서만 서비스에 진입합니다. opt-in 로컬 PostgreSQL 통합 테스트 8건에서 PAPER/REAL 주문 의도 저장·재조회, 동일 브로커 주문번호 환경 분리, 환경 간 멱등 키 재사용 거부, persistence context 초기화 및 Spring 애플리케이션 컨텍스트 재시작 후 미체결 주문 복구, 동시 동일 키 제출의 단일 주문 수렴, 체결·현금·포지션 정산과 중복 체결 키의 1회 반영을 확인했습니다. 별도 JVM 프로세스를 강제 종료하고 새 JVM에서 PAPER 주문을 조회·멱등 재제출하는 복구 스크립트도 통과했습니다. DB 접근·커밋 실패와 실제 PostgreSQL 중단 시 조회 실패는 인프라 정보를 숨긴 HTTP 503으로 반환합니다. 격리된 임시 PostgreSQL 인스턴스에서 주문 저장→DB 중단→503 확인→DB 재시작→동일 PAPER 주문 복구 시나리오를 `test-postgres-outage-recovery.ps1`로 검증했습니다. 테스트 DB와 API 프로세스를 정리하며 사용자 DB `localhost:5432` 및 KIS API는 사용하지 않았습니다.
3. **P3:** 단일 세션 ORB/VWAP/EMA/ATR 롱 전략과 상대거래량·스프레드·거래대금 필터, 다음 봉 진입, 비용·슬리피지 및 보수적 스톱 체결을 구현했습니다. 상대거래량 20은 직전 20개 봉과 현재 봉이 모두 확보된 뒤에만 평가하도록 했습니다. CSV 세션 그룹과 백테스트 결과 일자는 `--market`에 해당하는 거래소 현지시간(KR 서울, US 뉴욕)으로 산출하며, 한국 시간으로 저장된 미국 장 데이터가 자정을 넘어도 단일 미국 세션으로 유지됩니다. CSV 해시와 로컬 저장·백테스트 허용을 담은 권리 manifest를 확인한 뒤 시간대 포함 CSV를 한 종목 단위로 검증·분리해 세션별 재현 백테스트를 실행하고, PostgreSQL 저장 분봉을 권리 확인 대기 상태의 로컬 CSV와 sidecar로 내보내는 CLI를 추가했습니다. 결과에 데이터 SHA-256·비용 가정·범위를 기록합니다. KIS 국내 전체 세션은 최대 6개 120봉 페이지로 이어 조회할 수 있고 출처 포함 선택적 PostgreSQL 저장을 지원합니다. KIS PAPER 국내 분봉 381개를 실제 읽기 전용으로 조회해 전체 세션 경계(09:00–15:30)를 확인했고, 응답에는 과거 스프레드가 없어 진입 신호 0·체결 0으로 fail-closed 처리됨을 확인했습니다. 이 데이터는 저장하지 않았으며 이 결과는 전략 성능 검증이 아닙니다. 해외 분봉은 공식 KIS 규격상 모의투자를 지원하지 않으며, 해당 읽기 전용 조회는 REAL 시세 인증만 허용합니다. 이 API는 커서 기반이므로 임의 과거 날짜를 지정해 조회할 수 없고, `session_date`는 최신 페이지를 필터링할 뿐입니다. 두 REST 차트 모두 과거 호가 스프레드는 없어 null로 유지합니다. paper WebSocket 실시간 집계봉은 당시 호가 스프레드와 함께 비동기 PostgreSQL 저장을 선택할 수 있고 DB 저장 실패를 상태에 노출합니다. 회귀 검증은 Python 164건 통과. 실제 호가 스프레드가 수집된 다중 세션과 체결비용을 반영한 전략 성능 검증은 여전히 남아 있습니다.
4. **P4:** LightGBM/XGBoost 학습 파이프라인, 날짜 순서 데이터 분리, 피처/레이블 생성, 모델 해시·메타데이터 등록과 비실행 추론 미리보기를 구현했습니다. 한국/미국 거래소 현지 시간대로 장 진행률을 계산하도록 수정하고 피처 버전 잠금을 넣어 이전 피처 정의로 학습된 모델은 승인·선택·추론되지 않게 했습니다. 추론에 필요한 최소 과거 봉 수를 상대거래량 lookback에 맞췄고 API 요청도 21개 미만 봉을 거부합니다. 학습기와 백테스터가 동일한 CSV 검증기를 사용해 시간대 누락, 비정상 OHLCV, 정렬 오류 및 여러 종목 혼합 입력을 거부합니다. 학습은 CSV 해시와 로컬 저장·모델 학습 허용이 결합된 권리 manifest가 있을 때만 시작합니다. 학습 manifest에 출처·약관 참조·검토자·허용 범위·원본 CSV SHA-256과 모델 아티팩트 SHA-256을 기록하며 권리 정보가 없는 모델은 승인·활성화하지 않습니다. PAPER 주문 작업과 독립적으로 PAPER 국내 및 REAL 읽기 전용 미국 WebSocket 분봉을 PostgreSQL에 저장하도록 수집 경로를 검증했습니다. 모델별 미사용 테스트 세션에서 PAPER 런타임과 같은 퀀트 통과 AND AI 통과 신호를 P3의 다음 봉 체결·손절·익절·수수료·슬리피지 백테스터로 평가하고, 같은 세션의 퀀트 단독 체결결과와 손익을 비교해 manifest 및 대시보드에 저장합니다. 모델 manifest는 label horizon, 왕복 label 비용, 수수료·슬리피지와 유동성·손절 설정을 보존합니다. 1주/세션 독립 결과는 계좌 복리·시장충격을 반영하지 않습니다. 보조 양성률·평균 전방 순수익률은 겹칠 수 있는 개별 표본 레이블 통계이며 체결 실적이 아닙니다. Python 전체 테스트 168건 통과. 실제 허가된 시장 데이터에 대한 학습·모델 대 퀀트 성능 비교와 운영자의 출처·약관 확인은 남아 있습니다.
5. **P5:** KRX/NYSE 거래소 세션 달력, 분 단위 거래틱→봉 집계, 시세 지연/AI/브로커 상태 및 손실·포지션·장마감 기반 진입 차단기를 추가했습니다. 위험 한도는 `.env_local`에서 읽고 잘못된 값은 거부합니다. 주문 수량 계산은 거래당 0.25% 위험 예산, 종목당 자산 10%, 가용 현금과 주문 한도의 최소값을 적용합니다. paper ledger에서 연속 손실 매도 주문 수를 계산합니다. opt-in WebSocket 세션 monitor는 활성·승인 모델의 ORB/VWAP 후보를 검증하고 장 시작 3분 내 통화별 일손실 기준선을 최초 1회 저장합니다. 평가액은 현금+보유 수량×신선한 시세로 산출하며 KRW/USD를 환산하지 않고, 보유 시세가 누락·지연되거나 기준선 캡처 창이 지나면 신규 진입을 차단합니다. 국내 KR feed는 PAPER WebSocket, 미국 feed는 명시적 `KIS_REAL_WEBSOCKET_MARKET_DATA_ENABLED=true`와 별도 REAL 자격정보를 요구하도록 분리했습니다. 미국 실시간 연결은 읽기 전용 지연 시세를 paper ledger에만 공급하고 주문 권한은 사용하지 않습니다. 각 시장 연결은 독립 재연결 작업과 상태를 가지며, 하나의 feed가 끊겨도 나머지 feed의 데이터 수신은 계속됩니다. `KIS_SNAPSHOT_PERSISTENCE_ENABLED=true`이면 시작 시 해당 시장의 현재 세션 분봉을 DB에서 복원해 지표 준비 상태를 유지하고, 복원 오류 시 feed 연결을 막습니다. PAPER 자동매매를 별도로 켤 때 이 저장·복원 기능이 비활성화되어 있으면 잘못된 재시작 후 ORB 구간 계산을 막기 위해 monitor를 시작하지 않습니다. WebSocket 연결이 짧게 반복되는 경우에도 지수형 재연결 대기가 유지되고, 60초 이상 안정 연결 후에만 대기를 초기화합니다. 모의 WebSocket 반복 단절 테스트에서 2·4·8·16·30초 대기를 검증했습니다. KIS `PINGPONG` 제어 프레임은 상류 WebSocket Pong으로 응답해 PAPER 감시기와 로컬 시세 릴레이의 연결을 유지합니다. 재연결·대기 중 과거 신호가 늦게 처리되어 주문되지 않도록 신호 봉 기본 최대 나이 120초도 확인합니다. 신규 paper 매수는 승인 AI 후보, 일손실 1%, 연속 손실 3회, 총 보유 3종목, 미체결 주문 없음, 위험 예산 0.25%, 종목 자산 10%, 가용 현금 및 주문 한도 검사를 모두 통과해야 합니다. Spring은 체결과 손절·익절 가격을 트랜잭션 단위로 저장하고 local paper worker는 멱등 대조 후 기존 포지션을 손절·익절·장마감 청산합니다. 기본 잠금이며 KIS 실제 스트림의 연속 세션 검증과 비용·세금 반영은 남아 있습니다.
6. **P6:** Spring Boot KIS paper 지정가 주문·취소, 계좌 사전 확인, 영속 주문 의도와 중복 재전송 방지를 구현했습니다. V10은 PAPER/REAL 환경을, V11은 환경별 주문번호 유일성을, V12는 paper 체결비용을 저장하고 V15는 PAPER 주문·포지션의 전략 및 AI 모델 ID를 보존합니다. REAL 위험 게이트와 별도 잠금형 어댑터, 3초 만료·주문 내용 결합형 위험 승인, DB 선기록 오케스트레이터, 잔량 취소 및 국내·미국 체결 조회를 추가했습니다. 국내 전량 취소는 KIS 계약대로 `QTY_ALL_ORD_YN=Y`와 `ORD_QTY=0`을 사용하며 PAPER·REAL 요청 테스트로 확인합니다. 조회번호가 있는 REAL 접수/부분체결/취소대기 건을 주기적으로 대조하는 scheduler는 `KIS_REAL_RECONCILIATION_ENABLED=false` 기본 잠금입니다. 주문번호 없는 UNKNOWN은 자동 조회 추측·재전송하지 않습니다. Spring 테스트 110건 중 98건 통과·12건 건너뜀이며 로컬 PostgreSQL 통합 테스트 8건을 별도로 실행해 통과했습니다. 실제 KIS 주문은 보내지 않았고 REAL 주문 세 잠금과 계좌 읽기는 계속 false입니다.
7. **P7:** Next.js 조회 전용 상태 대시보드, 일일 JSON 리포트와 로그인 시 Spring Boot/Python 기동·장애 재시도·프로세스 트리 정리를 수행하는 Windows 작업 예약/제거 스크립트는 실행 중 `.env_local` SHA-256 변경을 감지해 양쪽 API를 정리하고 새 설정으로 재기동하며, fixture 검증은 자격정보 재적용·오래된 KIS 환경변수 제거·실전 주문 잠금 강제를 확인합니다. 자동 PAPER 진입의 전략·모델 ID를 주문·포지션·청산에 보존하고 전략·모델·종목별 매도 주문 승·패·승률·평균손익·기대손익·손익비·실현 하락액을 분석(체결 원장 평균원가 재생), paper 총액/비용후 손익, 오늘 체결 비용, KR/US 모델 승인·활성화·롤백 감사기록, 국내 PAPER와 미국 REAL 읽기 전용 시세 feed별 연결 상태, P5 판단 사유와 REAL 주문 의도 상태/대조 잠금을 표시합니다. feed가 모두 연결되기 전에는 전체 정상으로 보이지 않도록 부분 연결 상태도 구분합니다. 모델 카드에 입력 데이터·아티팩트 SHA-256과 권리 manifest 검증 상태를 표시합니다. 권리 자료가 빠진 구형 모델은 승인·활성 상태로 취급하지 않습니다. 모델 승인·활성화·롤백은 32자 이상 로컬 토큰을 요구하며, 미설정·불일치 시 각각 거부합니다. 같은 프로세스에서 동일 모델 디렉터리를 사용하는 API 요청은 거버넌스 잠금을 공유합니다. 모델 메타데이터와 활성 포인터 변경은 감사 로그 저장 실패 시 원복하고 로그를 디스크에 동기화합니다. 모델 카드에는 미사용 세션의 정확도·AI 후보 양성률·후보 비중과 비용후 평균 전방수익률, 퀀트 기준선의 동일 지표를 나란히 표시하며, 이 레이블 통계는 실제 체결 수익이 아님을 밝혔습니다. paper 비용 모델은 KR/US별 수수료 및 매도 비용 bps를 설정하고 체결 시 현금·평균원가·DB 비용·net 손익에 반영합니다. 기본 비활성이고 예제 0 요율은 계좌별 요율이 아니므로 실제 적용 요율 설정이 남아 있습니다. 검증: Windows 로그인 자동 시작 작업의 실제 API 기동, Python 강제 종료 감지 후 15초 재시도 대기를 거쳐 두 API 자동 회복, 작업 해제 시 하위 프로세스 정리를 확인했습니다. Spring 110건 중 98건 통과·12건 건너뜀, 로컬 PostgreSQL 통합 8건과 별도 JVM 재기동 검사 통과, Python 168건 통과, Next.js lint/build 통과. paper 연속 세션/장시간 장애 검증, KIS 실제 계좌 연결 및 비용 대조, 비용률 설정, 허가된 시장 데이터에 대한 모델 성능 비교는 남아 전체 P7 운영 승인 조건을 충족하지 않습니다. P7 모델 승인은 최소 5개 서로 다른 held-out 세션·5개 AI+퀀트 체결과 퀀트 단독 대비 양수 초과 순손익을 요구하며, 승인 감사 이벤트에 두 전략 손익·데이터 해시·모델 해시를 포함합니다.

이 단계별 상태는 코드 검증과 실제 KIS 계정 검증을 분리해 기록합니다. 계좌 키 없이 Mock 테스트는 통과하지만, 이는 실제 KIS 연결 성공을 뜻하지 않습니다.

## 2026-11-06 추가 통합 검증

- **P1:** 실제 KIS PAPER 국내 매수가능금액 GET 응답은 정상인데, Spring이 `Instant`를 JDBC에 직접 넘겨 계좌 스냅샷을 저장하지 못하던 문제(SQLState `07006`)를 확인했습니다. UTC `OffsetDateTime`으로 변환해 저장하도록 수정했고, 수정된 Spring을 재기동한 뒤 `069500` 조회에서 매수가능금액 포함 KIS PAPER GET 및 PostgreSQL 스냅샷 저장이 통과했습니다. 계좌 금액·보유 데이터는 로그와 보고에 출력하지 않았습니다.
- **P6:** KIS PAPER 계좌에서 1주 매수 주문을 접수·즉시 취소·대조할 opt-in 스크립트를 추가했습니다. 실행 확인 스위치, PAPER 주문 설정, REAL/자동매매 잠금, 최신 시세 대비 5% 이상 낮은 지정가, 주문 금액 상한, 고정 멱등 키 재조회 정책을 검사합니다. 현재 `KIS_PAPER_ORDERS_ENABLED=false`이므로 실제 모의 주문·취소는 실행하지 않았습니다. Spring 기본 테스트 110건은 통과했고 12건은 opt-in 통합 테스트라 건너뛰었습니다.
