# AI Stock Trader v1.0 Roadmap

## 방향

AI와 퀀트 전략 결합형 국내·미국 당일매매 시스템입니다. 기본 증권사는 KIS Open API입니다. NautilusTrader와 강화학습은 사용하지 않습니다.

초기 운영 한도(종목당 자산 10%, 거래당 0.25%, 일일 손실 1%, 최대 3종목, 연속 손절 3회)는 전략 검증용 시작값이며 수익 보장이나 최적값이 아닙니다. 설정값으로 관리하고, 고정 상수로 매매 판단에 박아 넣지 않습니다.

## 단계와 통과 기준

1. **P1 — KIS 연결 기반:** 별도 paper/real 인증, 국내·미국 잔고·주문가능 금액, WebSocket·호출 제한·마스킹. Mock과 paper 통합 조회를 검증하며 주문은 비활성화.
2. **P2 — 주문 엔진:** 매수·매도·정정·취소, 부분체결·중복 차단·재시작 복구. 모의 전 과정과 장애 시나리오를 통과.
3. **P3 — 퀀트:** VWAP, ORB, EMA, ATR, 유동성, 비용 모델. 과거 데이터 결과 재현과 미래 데이터 누수 방지.
4. **P4 — AI:** LightGBM/XGBoost, 피처·모델 버전·실시간 추론. 미사용 데이터에서 퀀트 대비 성능 비교.
5. **P5 — 자동 모의운영:** 국내·미국 시장 세션, 장 마감 관리, 장애 시나리오. 연속 모의 세션에서 안정성 확인.
6. **P6 — KIS 주문 엔진:** 모의 주문·취소 어댑터, 계좌잔고/주문가능금액 사전검사, 영속 중복방지와 불명 결과 잠금을 구현합니다. 주문 의도에는 PAPER/REAL 환경을 명시적으로 저장해 계좌별로 구분합니다. 실제 주문은 별도 승인 절차와 검증 기준을 통과하기 전까지 비활성화합니다.
7. **P7 — 운영·성과 개선:** 상태 대시보드, 일일 리포트, 시장별 모델 분리, 승인·활성화·롤백 감사 기록을 구현합니다. 운영 완료 기준에는 P1 계좌 연결, P5 연속 모의세션, 체결비용을 포함한 손익 대조와 검증된 데이터가 추가로 필요합니다.

## 구현 현황 (2026-11-07)

### 현재 P1 상태

P1의 구현과 2026-11-07 일회성 실계좌·모의계좌 읽기 전용 검증은 완료 기록이 있으나, **현재 P1 운영 통과 상태는 아닙니다.** 이후 PAPER 국내 잔고 502, 미국 잔고 시간 초과가 관측됐으며, 현재 Spring·Python API는 PostgreSQL의 `0.0.0.0`/`::` 비루프백 listener 안전검사 때문에 기동하지 못해 예약 작업이 비활성화되어 있습니다. 관리자 권한으로 `scripts/configure-postgres-loopback.ps1`을 실행하고 로컬 작업을 재가동한 뒤 여러 시점에서 PAPER 국내·미국 시세·잔고 읽기를 반복 확인해야 P1 운영 기준을 다시 통과시킬 수 있습니다. 2026-11-07 11:16 PAPER·11:20 REAL OAuth 점검에서, 11:22 PAPER GET에서 HTTP 403/502 `EGW00002`가 발생했으며 사용자의 지침대로 이를 일시 오류로 취급합니다. 이후 16:25 Spring PAPER 국내·미국 잔고 및 KRW/USD 주문가능액 GET 4건, 16:26 Python FastAPI 국내·미국 시세·잔고 GET 4건, 16:27 Spring REAL 국내·미국 잔고 GET 2건은 통과했습니다. 이 일회성 Spring 통합은 PostgreSQL 16.4/Flyway 21과 연결해 수행했습니다. PAPER 주문가능액은 KRW 70,000 기준 통과, USD 11 기준 미달이었습니다. REAL 조회는 별도 일회성 프로세스에서만 허용했으며 주문·취소 요청은 없었습니다. 현재 REAL 조회·PAPER/REAL 주문·REAL 대조·자동매매 잠금은 비활성 상태입니다.

1. **P1:** Spring REST 읽기 전용 계좌·잔고 기반과 Python REST/WebSocket 시세 연결을 구현했습니다. 양쪽 계좌조회는 전체 허용 스위치와 PAPER/REAL 환경별 스위치를 모두 확인해 REAL 조회가 기본 차단되도록 했습니다. 국내·미국 잔고 응답은 KIS의 연속 조회 헤더·커서를 따라 최대 20페이지까지 병합하고, 한도를 넘으면 불완전한 보유 목록 대신 오류로 닫습니다. 해외 잔고의 `output1` 보유 종목과 `output2` 요약을 공식 예제 형식에 맞췄습니다. 모의 체결기준 잔고 응답의 `output3.tot_asst_amt`는 총자산 평가액으로 분류하고 현금/주문가능액으로 오인하지 않도록 했습니다. 계좌별 현금 필드가 없는 경우 현금값은 미확인(null)으로 두며, 종목별 매수가능액은 별도 API 조회를 사용합니다. Python 계좌 클라이언트는 환경별 토큰 캐시를 재사용하고 앱 종료 시 HTTP 클라이언트를 닫습니다. 공유 제한 DB 오류는 Python API에서 HTTP 503으로 반환합니다. Python과 Spring은 PostgreSQL `kis_rest_rate_limit_slot`에서 환경·앱키 SHA-256 지문별로 슬롯을 원자 예약하여 프로세스 간 호출 간격을 공유합니다. Spring 4개 작업자와 Python 5개 작업자의 동시 예약을 실제 로컬 PostgreSQL로 검증했고, 앱키 원문은 저장되지 않습니다. DB에서 예약할 수 없으면 KIS 요청을 보내지 않습니다. `test-paper-kis.ps1`, Python FastAPI 국내·미국 시세 및 계좌 GET 스모크 `test-paper-kis-python.ps1`, 잠금 조건을 확인하는 `test-real-kis-account-readonly.ps1`을 준비했으며, 운영 요약은 비밀값 없이 PAPER/REAL 키 입력 및 10자리 계좌번호 형식 상태를 표시합니다. `.env_local`에 PAPER 인증값과 조회 잠금이 설정되어 있습니다. 사용자가 PAPER 계좌를 재등록하고 `.env_local`의 PAPER 계좌·키를 교체한 뒤, 2026-11-06 Spring PAPER 국내·미국 잔고 GET 통합 테스트 2건이 모두 통과했습니다. 이전 `OPSQ2000` 연결 오류는 갱신된 모의 계좌 등록/설정으로 해결되었습니다. 2026-11-07 전용 일회성 통합 테스트에서 실제 KIS REAL 국내·미국 잔고 GET 모두 통과했습니다. 조회 스위치는 해당 프로세스에서만 열었으며 `.env_local`에는 기록하지 않았고, 조회 후 운영 Spring API가 REAL 계좌조회·주문, PAPER 주문, REAL 대조 비활성 상태임을 확인했습니다. 주문·취소 요청은 없었습니다. WebSocket과 계좌 조회는 기본 잠금입니다.
2. **P2:** PostgreSQL 기반 paper 주문, 부분체결, 체결 중복 키, 포지션·현금 정산, 취소·만료와 기본 한도 검증이 있습니다. paper 주문 삽입은 PostgreSQL의 멱등 키 충돌 원자 처리를 사용하고, 만료 스케줄러는 paper 모드에서만 서비스에 진입합니다. opt-in 로컬 PostgreSQL 통합 테스트 10건에서 PAPER/REAL 주문 의도 저장·재조회, 동일 브로커 주문번호 환경 분리, 환경 간 멱등 키 재사용 거부, persistence context 초기화 및 Spring 애플리케이션 컨텍스트 재시작 후 미체결 주문 복구, 동시 동일 키 제출의 단일 주문 수렴, 체결·현금·포지션 정산과 중복 체결 키의 1회 반영을 확인했습니다. 별도 JVM 프로세스를 강제 종료하고 새 JVM에서 PAPER 주문을 조회·멱등 재제출하는 복구 스크립트도 통과했습니다. DB 접근·커밋 실패와 실제 PostgreSQL 중단 시 조회 실패는 인프라 정보를 숨긴 HTTP 503으로 반환합니다. 격리된 임시 PostgreSQL 인스턴스에서 주문 저장→DB 중단→503 확인→DB 재시작→동일 PAPER 주문 복구 시나리오를 `test-postgres-outage-recovery.ps1`로 검증했습니다. 테스트 DB와 API 프로세스를 정리하며 사용자 DB `localhost:5432` 및 KIS API는 사용하지 않았습니다.
3. **P3:** 단일 세션 ORB/VWAP/EMA/ATR 롱 전략과 상대거래량·스프레드·거래대금 필터, 다음 봉 진입, 비용·슬리피지 및 보수적 스톱 체결을 구현했습니다. 상대거래량 20은 직전 20개 봉과 현재 봉이 모두 확보된 뒤에만 평가하도록 했습니다. CSV 세션 그룹과 백테스트 결과 일자는 `--market`에 해당하는 거래소 현지시간(KR 서울, US 뉴욕)으로 산출하며, 한국 시간으로 저장된 미국 장 데이터가 자정을 넘어도 단일 미국 세션으로 유지됩니다. CSV 해시와 로컬 저장·백테스트 허용을 담은 권리 manifest를 확인한 뒤 시간대 포함 CSV를 한 종목 단위로 검증·분리해 세션별 재현 백테스트를 실행하고, PostgreSQL 저장 분봉을 권리 확인 대기 상태의 로컬 CSV와 sidecar로 내보내는 CLI를 추가했습니다. 결과에 데이터 SHA-256·비용 가정·범위를 기록합니다. KIS 국내 전체 세션은 최대 6개 120봉 페이지로 이어 조회할 수 있고 출처 포함 선택적 PostgreSQL 저장을 지원합니다. KIS PAPER 국내 분봉 381개를 실제 읽기 전용으로 조회해 전체 세션 경계(09:00–15:30)를 확인했고, 응답에는 과거 스프레드가 없어 진입 신호 0·체결 0으로 fail-closed 처리됨을 확인했습니다. 이 데이터는 저장하지 않았으며 이 결과는 전략 성능 검증이 아닙니다. 해외 분봉은 공식 KIS 규격상 모의투자를 지원하지 않으며, 해당 읽기 전용 조회는 REAL 시세 인증만 허용합니다. 이 API는 커서 기반이므로 임의 과거 날짜를 지정해 조회할 수 없고, `session_date`는 최신 페이지를 필터링할 뿐입니다. 두 REST 차트 모두 과거 호가 스프레드는 없어 null로 유지합니다. paper WebSocket 실시간 집계봉은 당시 호가 스프레드와 함께 비동기 PostgreSQL 저장을 선택할 수 있고 DB 저장 실패를 상태에 노출합니다. 회귀 검증은 Python 164건 통과. 실제 호가 스프레드가 수집된 다중 세션과 체결비용을 반영한 전략 성능 검증은 여전히 남아 있습니다.
4. **P4:** LightGBM/XGBoost 학습 파이프라인, 날짜 순서 데이터 분리, 피처/레이블 생성, 모델 해시·메타데이터 등록과 비실행 추론 미리보기를 구현했습니다. 한국/미국 거래소 현지 시간대로 장 진행률을 계산하도록 수정하고 피처 버전 잠금을 넣어 이전 피처 정의로 학습된 모델은 승인·선택·추론되지 않게 했습니다. 추론에 필요한 최소 과거 봉 수를 상대거래량 lookback에 맞췄고 API 요청도 21개 미만 봉을 거부합니다. 학습기와 백테스터가 동일한 CSV 검증기를 사용해 시간대 누락, 비정상 OHLCV, 정렬 오류 및 여러 종목 혼합 입력을 거부합니다. 학습은 CSV 해시와 로컬 저장·모델 학습 허용이 결합된 권리 manifest가 있을 때만 시작합니다. 학습 manifest에 출처·약관 참조·검토자·허용 범위·원본 CSV SHA-256과 모델 아티팩트 SHA-256을 기록하며 권리 정보가 없는 모델은 승인·활성화하지 않습니다. - **P6 REAL 보호청산 입력 영속화:** 서버가 승인한 모델 신호의 손절거리와 v1 보상/위험 배수 2.0을 주문 의도 저장 전에 같은 PostgreSQL 행에 기록합니다. 평균 부분 체결가를 기준으로 손절·익절 목표가를 재구성할 수 있고, PAPER/SELL 의도에는 보호 계획을 넣을 수 없습니다. 로컬 전체 Spring 회귀 252건(실패·오류 0, 선택 통합 27건 skip)과 보호청산 관련 집중 33건이 통과했습니다. PostgreSQL reload 통합 검증은 GitHub CI 실행 대상으로 추가했습니다. 이 데이터는 아직 잔고 감시나 자동 청산으로 연결되지 않았고 REAL 진입 잠금은 유지됩니다.
- **P6 보호청산 영속 상태·중복 선점 기반:** REAL 계획은 진입 주문 미확정 동안 `WAITING_FOR_ENTRY`, 잔여 매수 주문이 없고 체결이 확인되면 `ARMED`가 됩니다. PostgreSQL 조건부 갱신으로 동일 계획의 보호매도 의도를 단 한 작업자만 선점하고, 사유·수량·지정가·멱등키를 저장합니다. `EXIT_PENDING`도 재시작 조회에 포함했습니다. 로컬 전체 Spring 252건(실패·오류 0, opt-in 통합 27건 skip)과 PostgreSQL 통합 17건(실패·오류 0)이 통과했습니다. GitHub CI에서 V23 마이그레이션·원자 선점·재시작 조회를 확인했으며 실제 매도 주문 호출은 아직 연결하지 않았습니다.
- **P6 보호청산 신선 시세 입력:** Spring이 Python 시세 API를 통해 KIS REST 시세를 받아 시장·종목·미국 거래소·출처·3초 신선도를 검증하고 현재가와 bid/ask를 반환하는 경로를 추가했습니다. Mock 회귀 8건이 통과했습니다. 이 조회는 아직 감시 스케줄러에서 사용하지 않았으며 테스트에서 KIS API를 호출하지 않았습니다.
- **P6 보호매도 주문 시세 게이트:** REAL 매도 orchestrator가 승인 AI 모델 조회를 요구하지 않고 KIS 시세 서비스에서 최신 일치 시세를 검증하게 했습니다. 기존 REAL 계좌·매도 가능수량·장 운영·중복 주문·주문 한도 검사는 그대로 적용됩니다. 관련 Spring 테스트 36건 통과; 실제 계좌·KIS API·주문 호출은 없습니다. 보호청산 감시 스케줄러는 아직 구현되지 않았으며 REAL 자동 주문 잠금은 계속 닫혀 있습니다.
- **P6 보호청산 감시기·PostgreSQL 검증:** REAL 보호청산 감시, 신선한 KIS 시세·세션·계좌 일치 확인, 장마감 5분 전 청산 판단, 조건부 단일 선점, 같은 멱등 키 복구를 연결했습니다. 자동 보호매도 독립 스위치는 false이며 주문 대조 스위치가 닫혀도 감시기는 잠깁니다. CI에서 Spring 전체 266건 실패 0, PostgreSQL 통합 19건 실패 0, 전체 stack 성공, Windows PAPER 사전점검 성공을 확인했습니다. CI PostgreSQL에서는 감시기 저장 흐름과 동시 작업자 선점 경합도 검증했습니다. 로컬 Spring 262건도 실패 0(선택 통합 제외). KIS 실제 계좌·시세·주문은 호출하지 않았으며 P6 완료나 실전 가능 판정은 아닙니다. PostgreSQL 통합 중 발견한 pending 상태 제약은 V24로 수정했습니다.
- **P6 매도 전용 잔고 조회:** REAL 매도는 매수 가능금액 API를 추가 호출하지 않고 잔고·매도 가능 수량만 조회하게 했습니다. 보호청산 감시도 같은 읽기 전용 경로를 사용합니다. 국내·미국 매도 금액은 현금 잔액과 무관하므로 매수가능 조회 실패가 청산 검증을 막지 않습니다. 관련 Mock 테스트 17건 통과; 실제 계좌·KIS 호출 없음.
- **P6 PostgreSQL 감시기 통합검증 추가:** 실제 PostgreSQL 저장소에서 보호청산 감시기가 매도 의도를 원자 선점하고 동일 DB에 계획 상태·멱등키·가격을 남기는 통합 시나리오와 두 동시 작업자의 경합에서 선점 1건만 성공하는 테스트를 추가했습니다. Spring context에서 KIS 계좌·시세·주문 클라이언트는 Mock 처리하며 실 API 호출이 없습니다. 로컬에서는 opt-in 통합 테스트라 건너뛰고, 다음 CI 실행 결과 대기 중입니다.
- **P6 신규 REAL 진입을 보호청산 설정에 결속:** `REAL_PROTECTIVE_EXIT_MANAGER_ENABLED`만으로 매수를 허용하지 않고, 자동 보호매도와 KIS 주문 대조가 둘 다 켜진 경우에만 Spring REAL 매수/API 신호를 열도록 강화했습니다. Python 신호 전달도 동일 설정을 검사합니다. Spring 집중 테스트 18건, Python 신호 게이트 9건 통과. 이후 전체 CI Spring 266건 및 PostgreSQL 19건이 모두 실패 없이 끝났습니다. 모든 운영 스위치는 기본 false입니다.
